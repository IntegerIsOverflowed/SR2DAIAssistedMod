SR2D - change log
=================
Newest first. One entry per delivery; every entry says what was added / changed, which files,
and whether anything existing behaves differently ("compat" lines). The API details are in
README.md - this file is the "what happened when" record.

Entries from 2026-09-18 on are dated. The "[earlier NN]" entries reconstruct the deliveries
before the log existed, in order (higher number = more recent), without dates.

Conventions
  ADDED    new capability, nothing existing changes
  CHANGED  existing behaviour or API changed (a compat note says how to keep the old behaviour)
  FIXED    a bug
  DEMO     the demo app / strips
  TESTS    headless checks (tests/)
  DOCS     README / comments only

2026-10-09  animated SVG: optional precomposed bitmap loop (bounded memory, full-rate playback)
------------------------------------------------------------------------------------------------------------
ADDED  cs/Vector.Precompose.cs: third VectorSprite cache mode, opt-in Precomposed (default false).
       PrepareFilm(matrix, cancellationToken) bakes a Duration loop on an independent animated clone
       through the DIRECT renderer (not the approximate layer compositor), preserving clip owners,
       masks, morphs, opacity / dash tracks and use content. Clipped films store the container window;
       unclipped films union bounds at actual bake sample times (late-visible / travelling shapes).
       DrawAt(canvas, time, matrix), plus the position / scale / angle / pivot overload, selects a
       bitmap without evaluating vector tracks. Existing SeekToTime + Cached.Draw also works.
       Translation is free; changes to zoom / angle / skew, content Version, paint options, viewport
       flags / window / view box, duration / fps or budget invalidate the film. Precompose off,
       Invalidate, SetImage and Dispose release it; partial / cancelled bakes are disposed as well.
       MaxFilmPixels defaults to 64 M pixels = 256 MiB across ALL frames; 0 uses MaxPixels. If the
       loop does not fit, spatial resolution is reduced and the native bitmap path enlarges it;
       fps is NEVER silently reduced. FilmFrameRate = 0 uses Image.FrameRate, otherwise explicit.
       Invalid / empty / over-10000-frame loops and unusable budgets fall back live with a reason;
       the failed key is remembered (no expensive retry each tick). Old film freed before rebake.
       Diagnostics: FilmFrames / FilmFps / FilmScale / FilmSize / FilmPixels / FilmBakes /
       FilmBakeMs / FilmBlits / FilmActive / FilmStatus. SubPixel filters fractional placement
       without rebaking. Preparation is synchronous; first use / changed settings can take seconds.
CHANGED cs/Vector.Cache.cs: partial VectorSprite routes opted-in animated draws through the film;
       invalidate / dispose drop it; ScreenRect and LayerSummary understand the film. Default
       live-compositor and static-cache paths retain their behaviour and original signatures.
       cs/Vector.Anim.cs: CloneAnimated is internal (needed by the film's independent bake clone).
DEMO   demo/Tests.cs: Animated SVG has Precompose checkbox, film budget (MiB, default 256) and
       explicit bake fps (0 = file rate). Uses DrawAt for no-seek playback; note reports actual
       frame count, bitmap resolution, memory, bake time and frame draw cost. Old film released
       on file change; demo/MainForm.cs releases the animated cache on form close.
TESTS  tests/cs/vecrun: VECANIM gains film correctness, ownership, budget, key invalidation,
       wrapping, SubPixel, rotated window, late-bounds and fallback probes; optional real files
       also prepare a full-rate film, compare midpoint to direct, animate / reuse / release it.
       Verified: 128 ok / 0 FAIL with the synthetic file, all three friend scenes and cat.svg;

BUILD  demo and every explicit vector-source test project list cs/Vector.Precompose.cs; the

DOCS   README: API, lifetime, memory / spatial-quality trade-off, synchronous preparation and timings.
PERF   Release, AA on, advancing timestamps, 256 MiB budget (SPATIAL resolution is budget-limited):
       flask @600x400 direct 36.5 / layers 12.4 / film 0.48 ms, bake 9.2 s;

        pressure smaller bitmaps trade fine detail for RAM (raise budget or turn precompose off).

2026-10-09  animated SVG: layer compositor (cached rasters + live shapes) - 3-7x faster playback
------------------------------------------------------------------------------------------------------------
ADDED  cs/Vector.Cache.cs: VectorSprite now composites animated pictures (Tracks.Count > 0) in layers.
       The z order is split into runs of shapes whose animation chain only moves them (transform /
       motion tracks - camera dollies, parallax, static content); each run is baked once per zoom into
       a sub-raster (static chain + static clip form) and blitted per frame with the chain delta
       inv(base) - chain(t), re-rasterising only when the delta's linear part drifts beyond Tolerance
       (slow dollies re-raster ~2x/s). Shapes with morph / opacity / dash tracks, mask re-derivations
       or use sites are drawn live in their z slot. ClipViewport is honoured via the lock rect.
       New diagnostics: LayerSummary / LayerInfo; Rasterizations / CacheHits now cover the layers too.
ADDED  cs/Vector.Anim.cs: SeekToTime records the seek time; ChainDeltaOf(shape) = the animated delta
       over the static import chain (inv(BaseTransform) - Chain); TrackIsMover classification helper.
DEMO   demo/Tests.cs: the Animated SVG test draws through img.Cached (seek + compositor) instead of
       FrameAt per tick; the note shows compositor stats (layers / live runs / rasters / blits).
TESTS  tests/cs/vecrun: VECANIM gains 5 checks per file - cache stable at same t, reversible seek,
       cached frames match the direct renderer within 2% edge noise, mover tracks become layers,
       compositor honours ClipViewport.
DOCS   README.md: VectorSprite section documents the layer compositor and the measured speedups.
PERF   measured @600x400 / 1000x667 (seek + full draw, AA on): flask 30 -> 9.8 / 59.6 -> 19.6 ms,
       cauldron 10.4 -> 1.7 / 26.1 -> 3.6 ms, lab 15.9 -> 2.6 / 41.1 -> 5.9 ms.
compat: unchanged API; FrameAt stays exact. Animated pictures drawn through VectorSprite now render
        via layers (pixel-aligned rasters: anti-aliased edges may differ by <=1 px from direct draws,
        same trade-off the static cache always had). Static pictures unaffected.

2026-10-09  animated SVG: browser-fidelity fixes + ClipViewport
------------------------------------------------------------------------------------------------------------
  FIXED    transform chains compose in the right order now (child first, then parent - the
           row-vector form of the browser's column-vector chain). Before, an animated group
           around a statically-offset child rotated around the wrong point (the pestle that
           floated above the mortar), and an animated child inside an animated group (the
           hourglass sand inside the flipping group) turned around a different pivot than its
           glass. <use> sites get the site chain after the content chain; the import-time
           static chain is kept per shape (VectorShape.BaseTransform) so seeks rebuild the
           exact product.
  FIXED    clip-path clips live in their OWNER's user space: an animation on the clipped
           element (or between it and the owner) no longer drags the clip window along (the
           sand that spilled over the hourglass / slid down over the glass). SeekToTime
           re-derives such clips from the new VectorShape.ClipRoots (device-space clip + owner
           element) with only the owner's animated chain.
  FIXED    CSS opacity on an element the style hides (opacity:0 until animated - the bubbling
           idiom) shows now: the track value replaces the element's own opacity, the factor
           inherited from ancestors stays. `to`-only @keyframes sweep (implicit identity from)
           instead of holding still - the rotating pentagram runes.
  ADDED    VectorImage.ClipViewport (default off): drawing never paints outside the view box,
           for scenes that park dust / parallax / glow beyond the canvas. The demo's animated
           SVG test turns it on; browsers always clip to the viewport, so this matches them.
  CHANGED  vecrun's anim gate: 53 checks now (was 44) - static-clip-vs-animated-content, the
           opacity:0 idiom, to-only sweeps, nested static-offset-inside-animated-group order,
           ClipViewport on/off.

2026-10-08  CSS animations in SVG: @keyframes of transform / opacity (+ stroke-dashoffset)
------------------------------------------------------------------------------------------------------------
  ADDED    the SVG importer reads CSS animations now (the style AI-generated game art uses:
           @keyframes in <style> plus animation / animation-* on classes or inline styles).
           They become the same tracks SMIL produces: transform (per-function interpolation -
           rotate 0 -> 360deg sweeps a full turn; SMIL animateTransform rotates interpolate
           per parameter too), opacity (the track value replaces the element's own static
           opacity, inherited group factors stay) and stroke-dashoffset (marching dashes).
           Timing: shorthand + longhands, animation-delay, iteration counts, keyword and
           cubic-bezier easings, normal / reverse / alternate (-reverse) directions, fill
           modes; transform-box: fill-box + transform-origin: center (the design-tool default)
           turns rotate / scale around the element's bounds. Animated groups wrapping <use>
           (the camera-dolly pattern) move the use content with them. Other animated
           properties are reported once in Warnings (e.g. stroke-dashoffset is supported,
           anything else is not).
  CHANGED  the demo test is "Animated SVG (SMIL + CSS)" now (same button, same params); the
           vecrun gate checks a CSS spinner (fill-box origin, half turn at t = 1.0) and a
           delayed opacity blink in the synthetic file (44 checks, was 29).

2026-10-08  the darkening plate hugs the text's INK (Sprite.MeasureTextInk); extra width / height replace the inflate
------------------------------------------------------------------------------------------------------------
  ADDED    Sprite.MeasureTextInk (cs/Sprite.Text.cs) - where a text's INK sits, as DrawText would draw
           it: a rectangle relative to the draw origin, from the first to the last set pixel / row.
           The advance box MeasureText returns starts where a leading space starts and keeps the
           inter-glyph gaps; the plate (and anything that has to hug text) wants the pixels the eye
           sees. The text is rendered once into a scratch surface and scanned - exact by construction,
           for the pixel font, its weight and the fallback glyphs alike. Sprite.InkBounds is the
           reusable scan underneath.
  FIXED    the darkening plate was sized from the ADVANCE box: with the template's " Test form..."
           caption it started ~5 px left of the T (the leading space's advance) and ended at the drop
           shadow's last pixel. The plate is aligned to the ink now (BehindTitle = the caption's ink,
           BehindAllText = the ink of the caption plus every extra text), vertically to the ink rows.
  CHANGED  TitleDarkenInflate is replaced by TitleDarkenExtraWidth + TitleDarkenExtraHeight - how much
           WIDER / TALLER than the ink the plate is, per side (left + right / top + bottom).
  FIXED    the feather came out as "glitchy dark stripes": the edge ramp multiplied a PRE-SHIFTED
           alpha int, which overflowed the 32 bits. The ramp multiplies the alpha byte now, the corner
           pixels take the product of both ramps (a real separable 9-patch), and feather 0 / 0 adds
           exactly nothing - the plate is the ink plus the extras, to the pixel.
  TESTS    ctlrun +7 pins (340 total): the ink of "T" starts at its first set pixel, the advance box
           runs past a dot's ink, a trailing space does not widen the ink, a leading space shifts it by
           its advance, "H" spans the full glyph height, weight widens the ink by its px, only spaces =
           no ink.

2026-10-08  SpriteForm rework: the colour properties are real Color (the native designer cell); the title
            darkening is a feathered plate sized to the text
------------------------------------------------------------------------------------------------------------
  CHANGED  the SpriteForm colour properties (TitleBarColor, TitleTextColor, TitleTextShadowColor,
           BorderColor) and TitleTag's Color / ShadowColor are System.Drawing.Color now - a Color-typed
           property gets the NATIVE WinForms designer cell for free: the swatch rectangle, the colour's
           name or [A=, R=, G=, B=] values, and the drop-down arrow with the Custom / Web / System pages,
           exactly like BackColor. This replaces the int + ArgbColorConverter / ArgbColorEditor approach
           that never really matched the native cell; ArgbColorEditor is removed, ArgbColorConverter stays
           as the palette-list parser (StripeColorList / StripeColors are untouched, the array form stays
           the palette's property). The properties serialize as Color.FromArgb(...) in InitializeComponent
           and each carries Reset / ShouldSerialize for its default. COMPAT: code that set these as ints
           (TitleBarColor = -12763843) writes Color.FromArgb(-12763843) now; TitleTag's constructors take
           Color - wrap the old int literal in Color.FromArgb(...).
  CHANGED  the title darkening is reworked from "dim the bars under the text" (TitleBarsDarken
           None / Smooth / PerStripe with Strength / Feather / FeatherV / Height, which altered the bar
           colours) to a darkening PLATE: a black rectangle BEHIND the covered texts, sized to their pixel
           run and glyph rows, inflated around them and feathered at the edges. New API: TitleDarkenMode
           (None / BehindTitle / BehindAllText - the plate spans the caption, or the caption plus every
           extra title text), TitleDarkenInflate (px around the text, every side), TitleDarkenFeatherWidth
           (px the left / right edges fade over), TitleDarkenFeatherHeight (px the top / bottom edges fade
           over), TitleDarkenOpacity (0..100 %). Drawn after the bars and before the icon and the texts;
           the old per-bar / band dimming paths (DrawBars' second pass, DimUnderText, DarkenBand,
           DarkenVRamp, BlendToBlack) are gone - DrawBars paints the bars as they are. COMPAT:
           TitleTextDarken* properties do not exist any more.
  UPDATED  EmptySR2DFormTemplate to the user's cleaned rearrangement (the four test controls are gone,
           stripe bars 12 px) with the new plate knobs set (BehindTitle, inflate 5, feather 3 / 3,
           opacity 60); FeatureDemo's host form uses the new API; the demo's title tags pass Color.

  ADDED    Sprite.DrawMotionTaps (cs/Effects.cs) - motion blur that fits a frame loop. The
           existing Effects.MotionBlur / MotionBlurPath resample every pixel of the
           sprite-plus-trail image once per tap, which is exact and O(taps x (w+2M) x (h+2M)):
           right for an editor and for baking a blur into a sprite, wrong for a game frame.
           DrawMotionTaps covers the same trail with N whole copies of the sprite and AVERAGES
           them: one copy is premultiplied and scaled to 1/N, then added N times into a reused
           premultiplied accumulator with Op.Add (colour AND alpha add there, and N x 1/N never
           saturates, so the sum is the exact box mean rather than N copies piled up), and the
           accumulator goes over the destination with AlphaOver. The work is sprite-sized and
           constant whatever the trail length, and the picture is deterministic - unlike the
           feedback MotionEcho, a still object and a screenshot come out right at any frame
           rate. Measured here (256x256 sprite, 400 px trail, one draw; two runs of the same
           check): the taps 1.38 - 1.43 ms against 221 - 286 ms for the resampled blur, so
           160x .. 200x - the ratio itself moves between runs because the machine is slower or
           faster, while the taps' own cost barely does. The cost is honesty: a tap is a whole copy,
           so few taps on a long trail read as separate ghosts, not a smooth sweep. The scratch
           surfaces are [ThreadStatic], like VectorRender's, because the bench renders parallel
           bands through the same canvas.

2026-09-19  Editor blend modes (Photoshop / PDF): SR2D.BlendMode, Sprite.Blend.cs
--------------------------------------------------------------------------
  The 27 layer modes - Normal, Dissolve, Darken, Multiply, Color Burn, Linear Burn, Darker
  Color, Lighten, Screen, Color Dodge, Linear Dodge (Add), Lighter Color, Overlay, Soft Light,
  Hard Light, Vivid Light, Linear Light, Pin Light, Hard Mix, Difference, Exclusion, Subtract,
  Divide, Hue, Saturation, Color, Luminosity - with the PDF 1.7 / Photoshop formulas.

  Design: a mode IS an op code (32..58, above the classic ops), shared by SR2D.Op, SR2D.LineOp
  and the new SR2D.BlendMode enum, so every existing call that takes an Op / LineOp accepts a
  mode (Draw, MaskDraw, DrawScaled / DrawRotate2 / DrawQuad, DrawFx*, DrawBlurred, layers,
  shapes / text / selection fills). The compositing rule is the editor one and fixed: the mode
  acts on the colour, source alpha x opacity is the coverage ("mixed with alpha blend" built
  in; Normal == AlphaBlend). Destination alpha: untouched on a straight destination
  (AlphaBlend rule), PDF union / AlphaOver rule on a premultiplied one (Sprite.Premultiplied);
  premultiplied sources are un-premultiplied before the formula. Opacity (0..1) rides in the
  op word (bits 16..24), so layers with an opacity cost no extra pass.
