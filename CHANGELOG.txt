SR2D - change log
=================
Newest first. One entry per delivery; every entry says what was added / changed, which files,
and whether anything existing behaves differently ("compat" lines). The API details are in
README.md - this file is the "what happened when" record.

Entries from 2026-09-18 on are dated. The "[earlier NN]" entries reconstruct the deliveries
before the log existed, in order (higher number = more recent), without dates.

Conventions
  ADDED    new capability, nothing existing changes
  CHANGED  existing behaviour or API changed (a compat note says how to keep the old behaviour)
  FIXED    a bug
  DEMO     the demo app / strips
  TESTS    headless checks (tests/)
  DOCS     README / comments only


2026-09-27  Edit history (undo / redo), SpriteBox dirty-rect redraw
---------------------------------------------------------------------------
  ADDED    cs/EditHistory.cs: rect-based undo/redo for in-place edits. EditHistory.Record(sprite, rect) (or the
           VoxelGrid box overload) snapshots the affected pixels BEFORE a verb mutates them; Undo pastes them back,
           Redo re-applies the newer state (captured on the first undo). Only the affected rectangle is stored
           (Sprite.Pixels spans / the Voxel indexer), entries are independent snapshots on one timeline, a new record
           discards the redo tail, a memory cap (default 64 MB) drops the oldest entries first, and Undo validates the
           target dimensions instead of corrupting. Covers Sprite.Edit / Selection / effects and VoxelGrid edits
           through the public APIs. ctlrun: 12 new checks (pixel-exact restore, redo, tail discard, cap, dim
           mismatch, voxel box undo/redo), 112 total.
  ADDED    cs/SpriteBox: dirty-rect redraw. Redraw(Rectangle surfaceRect) re-renders only that region on the next
           paint - pending partials union into one clip, a full Redraw() supersedes them - and the Render handler can
           skip the rest via the new RenderEventArgs.ClipRectangle (Rectangle.Empty = everything; advisory: only the
           clipped region is guaranteed to hold the new picture). In classic mode (no SizeMode / FixedSurfaceSize)
           the invalidation is narrowed to the clip as well, so the blit side saves too; RenderOnce(Rectangle) runs a
           partial render synchronously for headless tests. ctlrun: 4 new checks (clip flow, union + clamp, outside
           pixels keep the previous frame, full-redraw supersede).


2026-09-27  Tween engine, fill patterns, perceptual wand + quick mask, Crossfade alias, toolbox icons, README
            cookbook
---------------------------------------------------------------------------
  ADDED    cs/Tween.cs: a small public tween engine - Tween.To(target, getter, setter, to, ms, easing) animates a value
           and invalidates the target every step (SpriteBox gets a full Redraw, others Invalidate). One shared 60 Hz
           pump, wall-clock paced (slow frames skip ahead, the duration stays exact), easings Linear / Smooth /
           EaseIn / EaseOut / Back, Completed event, Cancel / CancelAll, a per-target+getter auto-cancel so a new
           tween never fights an old one. Tests override Tween.Clock and pump deterministically. ctlrun: 6 checks.
  ADDED    cs/Sprite.Pattern.cs: image-brush fills - FillPattern(path, pattern, origin, scale, angle, tile, op,
           blendFactor, AA). The path is filled once into a scratch sprite (anti-aliased coverage in its alpha), the
           pattern is sampled through the inverse transform (wrap-tiling or single placement), coverage multiplies the
           pattern alpha, Set / AlphaBlend / Blend ops per pixel. Closes the SVG <pattern> / PDF pattern gap for
           editor-scale paths. ctlrun: 7 checks (tile phase + wrap in both axes, origin shift, AA edges, backdrop).
  ADDED    cs/Selection.cs: perceptual magic wand (SelectMetric.Perceptual - weighted RGB distance 0.30/0.59/0.11
           where the native max-channel metric overweights blue) and quick-mask round trips - ToSprite exports the
           coverage as an alpha mask you can paint with any verb, FromSprite reads it back (bounds recomputed).
           Found on the way and fixed: the weighted path cleared on Replace like the native one. ctlrun: 4 checks.
  ADDED    designer icons: 22 hand-drawn 16x16 32-bit BMPs (cs/icons/) embedded as namespace-qualified resources and
           wired via [ToolboxBitmap] on every Sprite control - the toolbox no longer shows the generic gear (the
           template and the demo csprojs embed them with a wildcard).
  ADDED    Sprite.Crossfade(src, x, y, factor): a descriptive alias of Blend(src, x, y, factor), so call sites never
           read like the unrelated Op.Blend draw mode (the standing naming trap).
  ADDED    README "Cookbook": ten recipes - mouse drawing, drag a sprite, zoomable viewer, game loop, saving without
           GDI+, undo, partial redraw, tweening, pattern fill, wand + quick mask.


2026-09-27  Diffuse border fold (Photoshop edge semantics), Code (F2) crash fix, keystroke drain fix, all
            headless runners on net10.0
---------------------------------------------------------------------------
  CHANGED  tests: every headless runner targets net10.0 now - one SDK for everything (the demo and the template
           were already net10.0-windows; ctlrun 140 ok, codechk 101/0, benchchk 0/0 both modes on net10 alone).
           While retargeting, four runners the last batches had left unbuildable were repaired: benchrun / vecrun
           glob cs/*.cs and now also exclude Tween.cs (it drags the WinForms shell types in), benchrun's stubs
           gained the FractalLayout.Regions geometry and the SwapDemo state that Tests.cs reads, blur gained the
           missing Selection.cs, and curvetest swapped its rotting hand-picked file list for the same broad-glob
           recipe (it had silently been compiling every runner's Program.cs). System.Drawing.Common bumped to
           10.0.0 across the runners.
  FIXED    native Effects.Diffuse: border pixels sampled the transparent work ring around the picture, and the
           old edge clamp let them pick themselves - opaque pictures got black holes creeping in from the
           edges while bright pixels stuck to / circulated along the borders instead of scattering away like
           Photoshop's Diffuse. Picks that leave the picture now fold back onto the outermost real pixel
           (reflect-101: no wrap-around, never the ring), and diffuse restores the transparent ring after the
           passes (POST resamples and draws onto larger destinations would have seen leftover ring content).
           Interior output is bit-identical to the old kernel; SSE2 and AVX2 agree. tests/cs/ctlrun pins the
           border contract: no bleed, no wrap, top-row dilution, ~1/9 corner self-pick on the narrow (LUT)
           and wide (formula) fold paths, flat stays flat, 1 px wide pictures fold cleanly.
  FIXED    demo: pressing Code (F2) crashed with IndexOutOfRangeException on the first coloured token of any test's
           code view. CodeView.Colorize already resolves each run's colour to the final Palette ARGB, but LoadCode
           indexed CodeView.Palette with that ARGB again - a double lookup (Palette[0xFF569CD6]) that throws before
           the first line ever renders. LoadCode now passes the run colour straight through; codechk pins the
           contract (every emitted run colour must be a Palette value) for all 101 tests, and a new headless harness
           replays For -> Colorize -> the LoadCode mapping for all 9 control-strip pipelines (the old mapping threw
           on 6617 runs, the new one on none). While in there: the code view of a strip test also falls back to
           src/FractalLayout.cs (now embedded), so the SwapDemo strip's source shows instead of "(source not
           available)".
  FIXED    demo: typing into the search box (and any text control) lost most keystrokes - only 1-2 characters got
           through. The game loop's inline message drain removed the pending WM_KEYDOWNs and dispatched them WITHOUT
           TranslateMessage, so no WM_CHAR was ever generated (the mouse never noticed: buttons need no translation).
           The drain now runs the classic TranslateMessage + DispatchMessage pump; keys that arrive while frames
           render reach the controls exactly as the main loop would deliver them.

  in; Normal == AlphaBlend). Destination alpha: untouched on a straight destination

  premultiplied sources are un-premultiplied before the formula. Opacity (0..1) rides in the
  op word (bits 16..24), so layers with an opacity cost no extra pass.
